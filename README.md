# QTSMC 答題紙批改

一個為老師而設的 MCQ 答題紙批改系統。上載掃描或 PDF 後，系統會在**瀏覽器內**找出三個答題框、讀取每格填畫、計算學生成績，並產生每題答對率及每個選項的百分比。所有影像及成績只留在使用者的瀏覽器（IndexedDB），不會上傳到伺服器。

> 第一張答題紙預設為**答案卷（滿分）**；可隨時改以另一張作答案卷。

## 功能

- **多種輸入**：JPG / PNG / WEBP 及多頁 PDF（PDF 自動逐頁拆開，並自動校正掃描傾斜）。
- **自動辨識**：定位答題框、校正輕微歪斜、自動處理 90° / 180° / 270° 旋轉。
- **自動光暗校正**：掃描會先做 Levels + Gamma 正規化，把紙底拉白、淡色鉛筆痕加深；對手機相片、影印件及光暗不均的掃描更穩定。
- **覆核可切換增強對比**：標記圖右上角可切換「增強中／增強對比」；以 Levels + Gamma 加深淡色鉛筆痕，紙底保持白色，此開關不影響已計算的分數。另有「原圖」按鈕隱藏所有標記。
- **答案卷與自動題數**：以第一張為標準；按答案卷及全班作答情況自動判斷本次題數（例如 24 題），未使用的 Q25–60 不會計入滿分。
- **答案卷預設不計入統計**：第一張只作答案標準，不會拉高全班平均或題目百分比；如想計入，可在匯出頁開啟。
- **自動班別／學號**：讀取左上角 Level / Class / Class No 的填畫，組合成班別（如 `4B`）及**兩位數學號**（取 Class No 最後兩位，例如 `18`）。四位數的考生號碼（例如 `4218`）會另外保留，用作全校名單配對。系統會提示未能讀取或重複的學號，方便手動覆核。
- **逐題覆核**：彩色標記圖顯示系統判定的答案；存疑、多選（multi）及 `blank` 會另外標示。需要覆核的學生一打開會先只顯示需覆核的題目，下方可按「顯示全部」查看全卷。
- **原圖／標記切換**：覆核畫面可按「原圖」隱藏所有彩色標記，只看掃描原稿；再按「顯示標記」回復。放大後可用滑鼠按住圖片上下左右拖曳平移。
- **blank 納入覆核**：成績表有「有 blank」篩選及「有 blank」狀態；按「需覆核」進入覆核畫面時，blank 題目亦會列出，方便檢查是否漏填或太淡。blank 仍然是 0 分，不會自動當作答對。
- **答案卷編輯器**：可直接修改任何一題的標準答案，成績即時重新計算。
- **全校名單自動配對姓名**：網站會自動讀取學校 Google Sheet 的 `Student_namelist` 分頁，按掃描到的班別＋學號填入中文姓名；老師只需上載 PDF，不需要另外匯入名單。名單快取在本機；如載入失敗，會在「需要留意」提供重試。
- **缺漏欄位會建議**：如果某頁沒有讀到班別／學號，系統會按上載順序和全校名單建議下一個學號及姓名，並以黃色欄位、「＊ 漏填學號」及匯出備註清楚標示，不會當成已確認資料。
- **姓名不詳保持空白**：若全校名單沒有對應班別／學號，姓名會留空（不會用 PDF 檔名或頁碼代替），並可在「姓名不詳」篩選中找到。
- **需要留意可直接篩選**：按「班別／學號」、「漏填學號」或「需覆核」會切到成績表並只顯示相關學生；「需覆核」包括存疑、多選及未填，與下方篩選數字一致。
- **覆核完成狀態**：在覆核畫面按「完成覆核」後，該學生的狀態會由「需覆核」改為「覆核完成」，並移出需覆核人數；重新批改全部會重設狀態。
- **姓名自動配對**：修改班別或學號後，系統會即時用全校名單重新配對姓名；插班生若不在名單中，姓名會留空（不會保留錯誤的舊建議）。姓名仍可手動修正作例外處理。
- **及格率自動切換**：按班別／header 的級別自動設定——高中（S4–S6）40%、初中（S1–S3）50%；可在匯出頁取消「自動」再手動指定。
- **全級＋班別統計**：平均分、中位數、最高/最低、標準差、及格率、分數分佈、每題答對率、每個選項（A/B/C/D/blank/multi）的人數及百分比；題目分析同時列出全級答對%及每班答對%，並有「班別統計」工作表。
- **按班分拆**：預設按班別加入班別統計、每班工作表及每班成績 CSV；選修科可在匯出頁取消「按班別分拆匯出」。
- **數學科分組統計**：如 `Student_namelist` 有 `Group` 欄（例如 `1A1`、`4AB2`、`6CD1`），數學科匯出會在全級及每班成績表加「分組」欄，並新增「分組統計」工作表及 CSV（各組平均、中位數、最高／最低、標準差、及格率、每題答對率）；名單未有分組的學生歸入「未分組」。
- **blank 顯示**：網頁以「未填／—」顯示；Excel、CSV 仍按你指定顯示 `blank`。
- **multi 顯示**：網頁逐題答案以「多選」及實際選項顯示，例如 `B, C`；Excel、CSV 直接列出所選字母。題目分析／選項統計仍以「多選」作為統計類別。
- **18 題或 24 題皆可**：系統按答案卷及全班作答自動判斷題數；也可以在答案卷編輯器手動設定。
- **匯出**：
  - Excel `.xlsx`：成績總表、題目分析、選項統計（長表，方便樞紐分析）、答案卷、統計摘要、設定；檔名為 `年級_科目_報告 All in one.xlsx`。
  - 所有報告及 PDF `.zip`：根目錄有完整 XLSX 及你上載的原始 PDF；`csv/` 資料夾內有五個主要 UTF-8（含 BOM）CSV，另加班別統計及每班成績 CSV。檔名為 `年級_科目_報告 All in one.zip`。
  - 成績總表同時包含：得分、百分比、答對／答錯、`blank`／`multi` 數目、**存疑題數**、備註及每題作答；每題 multi 會顯示所選字母（例如 `B, C`），blank 會顯示 `blank`。
  - 題目分析／選項統計包含每題答對率、A–D 及 `blank`／`multi` 的人數與百分比；統計摘要包含平均、中位數、最高／最低、標準差、及格率及分數分佈。
  - CSV 以 UTF-8 BOM 輸出，ZIP 內的中文檔名亦使用 UTF-8 flag；實測中文姓名、標題及百分比在 Excel／CSV 開啟時沒有亂碼。
  - JSON 備份：包含答案、設定、分數及自訂答案，不包含原始影像。
- **手機 / iPad 版面**：成績表有 sticky 欄位及姓名旁查看按鈕；手機預設先看學生卡，分數分佈／答案卷可收起；題目分析頁的 ANSWER KEY 在手機／iPad 預設收起，可按「查看答案」展開；題目分析在手機／iPad 會轉為卡片；覆核畫面在 iPad 為左右分欄、手機為上下分欄，並提供放大／縮小。
- **減少資訊負荷**：結果頁的多個警示合併為一行「需要留意」項目；重複的「管理答題紙」、答案卷長標籤及上載頁重複說明已移除；成績表「上載次序」排序選單的整個框都可點擊；重要操作（答案卷、匯出）仍然直接可見；「匯出成績」亦是結果頁的主要按鈕，按下會平滑捲到匯出區，成績表工具列另設匯出快捷。
- **多任務本機儲存**：可以同時保留多份卷。每一份卷有自己的 PDF 影像、成績、答案卷修正、姓名／班別／學號、題數、匯出設定、**年級及科目**；頁首右上角的「目前任務」選單可切換任務，按旁邊的「新任務」開始另一份卷。重新整理瀏覽器後仍會回到上次開啟的任務。
- **新任務先選年級及科目**：按「新任務」或第一次上載時，系統會要求先選年級（S1–S6）及科目，之後才建立任務或開始處理檔案；任務選單會以「年級 · 科目（頁數）」顯示。
- **年級及科目選單**：年級 S1–S6；科目按初中／高中分組，並可保留舊任務的自訂科目。年級會直接決定自動及格線（S1–S3 50%、S4–S6 40%），亦可在匯出頁更改。
- **簡潔起始畫面**：第一次未有任何答題紙時，只顯示「STEP 01 · 上載」及頁首的任務控制，不顯示大標題。
- **舊資料自動升級**：舊版只有一個工作階段；更新後會自動變成第一個任務，不需要重新上載。
- **頁尾版本號**：頁尾顯示 `vX.Y.Z`，方便確認老師正在使用哪一個版本。
- **本機自動儲存**：每次修改後約一秒自動儲存到 IndexedDB；「清除本任務」只會清除目前任務的答題紙，「刪除目前任務」會連同該任務的影像及成績一併刪除，其他任務不受影響。
- **隱私**：沒有後端、沒有 API key、沒有分析追蹤；影像不會離開裝置。

## 使用流程

1. 上載整疊答題紙（或一個多頁 PDF）。第一張會自動設為答案卷。
2. 按「開始自動批改」。系統會逐張辨識並顯示進度。
3. 到「成績總表」檢查學生姓名；按任何一行開啟標記圖覆核。
4. 到「題目分析」查看每題答對率與選項百分比；到「選項分佈」看視覺化分佈。
5. 在「匯出」填上測驗名稱、年級、科目、日期及及格分數，下載 Excel 或「所有報告及 PDF」壓縮檔。
6. 如要批改另一份卷，按頁首右上角的「新任務」，選好年級及科目，再上載第二個 PDF。完成後可用「目前任務」選單切回第一份卷，之前的影像、成績及設定仍然保留。

### 多任務與科目

- 任務選單會顯示「年級 · 科目（頁數）」，例如 `S4 · 物理（112 張）`；未設定時會以第一個上載的 PDF 檔名作名稱。
- 年級及科目屬於目前任務，會一併用於匯出及自動及格線；切換任務時會自動換成該任務的設定，也可在「匯出」頁更改。
- 第一次上載或按「新任務」時必須先選年級及科目；取消設定不會開始處理檔案。
- 「新任務」只會清空畫面，**不會刪除**上一個任務；有頁數的舊任務會保留在選單。要移除舊任務請按頁首的垃圾桶圖示（手機版可在頁尾按「刪除目前任務」），系統會要求確認。
- 多個任務會各自佔用本機 IndexedDB 空間；例如 150 頁約 53MB。長期使用可刪除不再需要的任務，或在瀏覽器設定中管理網站資料。

### 答案卷與題數

- 答案卷的第一題至最後一題有答案的範圍，就是本次測驗的題數（例如 18 題或 24 題）。
- 系統亦會參考全班作答：只有極少數頁面出現的「背後透印」或雜點，不會把題數拉長。
- 如自動判斷不準，可在「答案卷編輯器」直接修改「本次題數」（1–60），或補上/修改答案。若試卷只有 18 題，鍵入 18 後 Q19–60 便不會計分。
- 答案卷本身永遠以滿分顯示；答案卷預設**不計入**全班統計，可在匯出設定中開啟。

### 存疑與 multi

- `low`（畫面顯示「存疑」）：填畫較淡或分數接近，系統仍然給出答案，但會在覆核畫面標示，建議老師看一眼原稿。
- `multi`：同一題有兩個明顯填畫，系統不會猜其中一個，會顯示 `multi` 並以 0 分計。
- `blank`：沒有偵測到填畫，以 0 分計。
- 所有修正會即時影響成績、題目分析及匯出。

## 本機開發

需求：Node.js 20+。

```bash
npm install
npm run dev
```

開啟終端顯示的本地網址（預設 `http://127.0.0.1:5173`）。

生產建置：

```bash
npm run build
npm run preview
```

## 部署

本專案是純靜態 Vite 應用，已包含 `vercel.json`，可直接部署到 Vercel：

```bash
# 先部署預覽版（不影響現有 production）
vercel

# 確認預覽版無問題後，才切換正式版
vercel --prod
```

- GitHub repo：<https://github.com/kaileungkw/qtsmc>
- Vercel production：<https://qtsmc.vercel.app>
- 現時 Vercel 未連接 GitHub auto-deploy，所以 `git commit` / `git push` 只會更新原始碼，**不會**改動其他老師正在使用的 production；只有執行 `vercel --prod` 才會切換網址。更新前可先用 `vercel` 取得預覽網址試用，確認後才 promote。
- 版本號在 `package.json`；頁尾會自動顯示同一版本（例如 `v2.7.0`），方便核對同事正在使用哪一版。

GitHub Actions 會自動執行 `npm ci && npm run build` 作建置檢查（見 `.github/workflows/ci.yml`）。

如要每次 push 到 `main` 都自動部署，Vercel 的 GitHub App 需要授權此 repo（Vercel 帳戶目前只開放了部分 repo）。到 <https://github.com/settings/installations/96342233> 把 `qtsmc` 加入 Repository access，然後執行：

```bash
vercel git connect https://github.com/kaileungkw/qtsmc.git
```

目前 production 版本已由 Vercel CLI 部署；自動部署授權後即可改為 Git push 觸發。

## 技術原理

- 影像在 Web Worker 內以 1500px 工作寬度處理。
- 以積分影像做 adaptive threshold，找出所有深色像素。
- 掃描頁面上連續的長垂直線，配對成三個答題框；再以固定版面比例（在 21 頁真實掃描上量度）定位 20 × 4 格。
- 每格先以印刷氣泡邊框做 ±3px 對位，再量度中央区域的填畫深度；另以中央亮度中位數偵測很淡的鉛筆痕。
- 以答案卷及全班共識判斷實際題數，避免把背面透印當成答案。
- 匯出使用 ExcelJS（瀏覽器端產生 xlsx）及 JSZip（CSV 壓縮）；PDF 拆頁使用 PDF.js。

- 已用 21 頁真實 A4 掃描（舊 scanner PDF）測試：21/21 頁成功定位三個答題框，正確判斷 24 題，沒有 console error；Excel 與 CSV 內容、顏色、blank 顯示均已驗證。
- 已用**新 scanner 的 19 頁 PDF**（S5_Phy_MC，5A–5D 共 18 位學生）測試：19/19 頁成功定位及批改；自動判斷 24 題、18 位學生、平均 46.1%，姓名／班別／學號由全校名單配對。新 scanner 頁面有約 0.2° 輕微傾斜：系統會為每個答題框估計整體格線偏移，避免下方行數讀到氣泡邊框；原本 page 8／10 空白 Q41–60 被誤讀為 low／multi 的問題已消除。
- 第 15 頁的 Level／Class／Class No 填得很淡，而且 header 欄位有少許位置偏差；系統現在會逐個 header 欄位對位，並用氣泡內部核心的淡色點判斷，已成功讀成 5B17。page 9 的學生把資料寫在頂部交叉格而沒有填 bubble，仍會標示「漏填學號」，需人手確認。

- 已測試自動及格率：S5 班別自動用 40%，改成 3A 後自動切回 50%；取消「自動」可手動設定。
- 已測試姓名自動配對：把 5A04 的學號改成 5A18 會即時顯示名單姓名；改成不存在的 5A99 會留空。
- 已測試 multi 逐題顯示：例如同一題填 B、C，成績表、覆核畫面、XLSX 及 CSV 均顯示 `B, C`；blank 顯示 `blank`。
- 已用兩份各 3 頁的 PDF 測試多任務：兩份卷分別設定不同科目，切換後影像、成績、姓名及科目都正確還原；重新載入後仍停留在上次的任務；刪除任務及舊版單一工作階段自動升級亦已驗證。
- 手機 390px 實測：成績表會轉為學生卡，每位學生卡顯示全部 Q1–QN 作答選項，不會只看到姓名／班別／學號。
- 多任務功能以 IndexedDB 每個任務獨立儲存；瀏覽器清除網站資料仍會移除所有任務。
- 手寫姓名／科目**不會自動 OCR**；姓名由全校名單按班別／學號自動配對，插班生會留空；可在成績表手動補上。
- 如果班別／學號只寫在頂部交叉格而沒有填泡泡，系統不會亂讀空白泡泡；會按前後頁座位建議下一個學號（黃色、漏填學號），例如 5A38 → 空白頁 → 5B01 會建議 5A39，需人手確認。
- **掃描模式很重要**：請用灰階或彩色掃描（建議 300dpi 或以上）；影印機的「黑白／1-bit」模式會把淡鉛筆痕直接變成白紙，任何對比增強都無法復原。黑白模式只適合填得很深、很滿的記號。
- 班別／學號會嘗試讀取左上角填畫；如果學生把學號寫在格子上方而沒有填泡泡，或填得極淡，系統可能讀不到，會顯示提示讓你手動更正。
- 非常淡或已被擦除的鉛筆痕可能需要人手覆核；自動增強會盡量加深，但仍可能在該格顯示 `blank`，可用覆核畫面的「增強對比」核對原稿。
- 相片應包含完整答題紙；嚴重透視變形、手指遮蓋或裁切可能影響辨識。
- 建議使用最新版 Chrome、Edge 或 Safari（需要 Web Worker + OffscreenCanvas）。不支援的瀏覽器會顯示提示。

## 頁數與效能

- **沒有硬性頁數上限**；實際限制來自瀏覽器記憶體、CPU 及本機 IndexedDB 儲存空間。
- 已用 **150 頁 PDF** 在桌面 Chrome 實測：PDF 拆頁約 **9–13 秒**、批改約 **33 秒**、本機儲存約 **53MB**、150 位學生結果正常、自動儲存成功、0 個 console error。
- 大量頁數會自動收起縮圖（預設只顯示 8 張，可展開全部），並在頂部提供「開始批改」按鈕，不需要捲到最底。
- 手機／iPad 的 CPU 及儲存限制較大，建議每批 **50–80 頁**；150 頁建議用桌面 Chrome／Edge。
- 實際時間會受 PDF 大小、掃描解像度及裝置速度影響；60 題的處理時間會比 24 題長。
- 所有頁面都在瀏覽器內處理，Vercel 沒有頁數或上載流量限制。

## Vercel 用量與收費

- 這是**純靜態網站**，沒有 Serverless Function、沒有後端資料庫。Vercel 只負責送出 HTML/CSS/JS 檔案。
- 老師上載的掃描影像**不會經 Vercel**；辨識、計分及 Excel/CSV 產生全部在瀏覽器內完成，所以不會消耗 Vercel 的 Function 執行時間。
- 第一次開啟約下載 1–2 MB 程式（之後由瀏覽器快取）；ExcelJS、PDF.js 等會按需要才載入。以校內幾十位老師、每班幾十份卷的使用量，Vercel 免費 Hobby 計劃的每月 bandwidth 一般足夠。
- 如學校大量使用或需要自訂網域／密碼保護，可再考慮 Vercel Pro 或把 `dist/` 放到校內伺服器；程式本身不需要 Vercel 才能運作。
- 如果網站已部署新版本，而你仍開住舊分頁，舊版的下載程式檔可能已不在伺服器（表現為 `Failed to fetch dynamically imported module`）。系統會提示重新整理；現有任務保存在本機，重新整理後會自動返回「匯出」頁，再按一次下載即可。

## 私隱

本工具沒有後端。所有掃描影像只會存在瀏覽器記憶體及本機 IndexedDB；關閉或清除瀏覽器資料後便會移除。部署到 Vercel 只是提供靜態程式檔案，不會接收或儲存任何學生資料。

全校姓名來自學校的 Google Sheet（`Student_namelist` 分頁），由瀏覽器即時讀取並快取在本機；名單**不會**被寫入 GitHub 或 Vercel 的程式檔。數學科分組同樣只讀取該 Sheet 的 `Group` 欄，網站不會另存分組名單。若把該 Sheet 改為私有，網站會退回「名單未載入」，老師仍可手動／批次輸入姓名。請按學校的個人資料政策管理名單的分享設定。
